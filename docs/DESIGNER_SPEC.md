## 2. Look

- **Materials and finishes** (Art): per-part finish slot: bare metal, white paint, cork/insulation, carbon, soot weathering (cosmetic only; structural material stays the engineering field above).
- **Liveries**: earned by play only. Unlock rules are public on the card before you earn them ("Reach orbit 3 times"). Never sold, never time-limited, never random, nothing expires, no streaks. All earned liveries stay forever.
- **Decals**: up to 6 per vehicle, placed on preset anchor rings (stage band, interstage, fairing), scale 3 steps, rotate 0/90.
- **Branding editor** (original, fictional): vehicle name (existing `livery.name`, 1-20 chars, profanity filter offline), a mark built from shapes (pick 1 of 12 base glyphs + 1 of 6 frames + colour), primary/accent colours (existing `livery.primary/accent`) from a 16-colour palette plus a hex field in engineer. No real trademarks or agency marks: the editor ships no letterforms or logos copied from real companies and no real pad names. The catalog review rejects anything resembling Blue Origin, New Glenn, Jacklyn, LC-36, or agency logos.
- **Scope conflict:** `docs/DECISIONS.md` #48 defers free-form livery and exploded views to 1.1. This spec keeps the branding editor template-based (glyph + frame + palette, not free-form drawing) so it can ship in 2.0, and it marks the exploded view **2.0 if Graphics fits it, else 1.1**. The lead needs to confirm.

## 3. Live readout

| Number | Source | Kid (simple) | Standard | Engineer | Units |
|---|---|---|---|---|---|
| Total Δv vs required | `QuickReadout.totalDeltaV/required` | ✓ as "Speed budget" with a bar | ✓ | ✓ + margin % | m/s |
| Pad TWR | `liftoffTWR` | ✓ as "Liftoff push 1.4 × weight" | ✓ | ✓ | ratio |
| Per-stage Δv, TWR SL/vac | `stages[i]` | — | ✓ table | ✓ + m0 | m/s, ratio |
| Total and per-stage mass | `mass`, `stages[i].m0` | — | total | ✓ + dry/prop split | t |
| Max-Q estimate | new in Core (web `readout.js` L112 has `maxQ` from sim) | — | ✓ | ✓ | kPa |
| CG, CP, stability margin | new in Core | — | "Stable / Twitchy" word | ✓ positions + margin | m from base; calibres |
| Cost | `cost`, `CostModel.FormatKc` | ✓ | ✓ | ✓ + category split (`CostModel.CATEGORIES`) | kc (fictional credits) |
| Reliability | `reliability` | — | ✓ | ✓ | % |

- Δv uses Tsiolkovsky per stage, Isp interpolated sea level -> vacuum for stage 1 / boosters and vacuum for upper stages (as `Headless.StackDeltaV`). Max-Q is an estimate from a fixed reference ascent, labelled "≈".
- **Latency:** quick numbers (Δv, TWR, mass, cost, CG/CP) update the same frame as the edit (≤16 ms on SE). Max-Q (needs a sim) is debounced 300 ms like web `SIM_DEBOUNCE_MS` (ui.js L22) and shows "≈ …" until ready.
- **Honest physics note** (shown under the readout in engineer, in the Codex for kids): "Numbers come from the same model as flight. Max-Q is an estimate from a standard climb. Costs are fictional credits."

## 4. Presets and depth

Kid presets (cards, 56 pt): **Hopper** (1 stage, small kerolox, legs, suborbital), **Workhorse** (= `stock`), **Heavy** (= `super-heavy` or stock with 4 boosters), **Lander** (2 stages, landing reserve + legs + fins). Existing `scout` and `kid` stay under "More". Each preset forks with `meta.forkedFrom` (`web/js/designer/templates-fork.js` L4) so compare can diff it.
Depth unlocks only by progress (`standard` after the first orbit) or the Settings Engineer toggle (`Experience.Resolve`). Never by payment, energy, or timers. Locked rows show a single line: "Opens after your first orbit, or turn on Engineer in Settings." "Make it fly" (`Validate.MakeItFly`) is always available and lists what it changed.

## 5. Undo, compare, save, view

- **Undo/redo:** 50 steps per session, one step per committed edit (stepper release / slider end, not every tick). Buttons in the header (44 pt) plus a three-finger swipe left/right (system gesture) and shake-to-undo off by default. VoiceOver: "Undid: stage 1 engines 9 to 8".
- **Compare (A|B):** pins the current design as A, edits continue on B; side-by-side readout table with deltas, and both vehicles at the same scale. On iPad both render; on iPhone a toggle flips the 3D view. The table component is shared with the Vehicle Data Sheet compare view (UX owns both; same columns and order).
- **Save slots:** 8 local slots, named (default = preset name), duplicate, rename, delete with plain confirm ("Delete Slot 3? This can't be undone." Delete / Keep). Local only via the existing store keys (`kh.save.v1.design.*`, `web/js/designer/store.js`; Unity `Kestrel.Core/Save/NativeStore.cs`). No cloud, no account.
- **3D:** one-finger drag rotates about the vehicle axis (yaw only, ±180°), pinch zooms 0.6x-3x around the touched part, double-tap reframes with `DesignFraming`. Exploded view separates stages, boosters and fairing along the axis by 0.15 x stage height with an eased 400 ms animation (instant with Reduce Motion). Tapping a part in 3D selects it in the stack list.

## 6. Validation

Every edit calls `Validate.Engineering(catalog, designJson)` then `Experience.Present(report, layer)`.
- **Inline:** an issue with `index` (or matching `tab`) puts an amber (warning) or red (block) ring on the part row, the tab chip, and the 3D part.
- **Summary chip** top-left under Home: kid "1 thing to fix" / engineer "1 block · 2 warnings". Tap lists all issues; tap an issue jumps to its tab and part.
- **Launch:** disabled while `report.ok == false`, with the first shown block under the button ("Fix first: …"). Warnings never disable Launch.

## 7. Layout

**iPhone (SE and Pro Max), portrait.** Top to bottom: safe area · header row 44 pt (Home 74 pt wide, slot name, Undo, Redo, A|B) · summary chip · 3D vehicle · bottom panel. The panel keeps the merged #115/#122 behaviour: 56 pt handle, tap or 24 pt drag toggles (`SliceApp` L74-81), collapsed = handle + bottom safe area (L139), camera framed above the panel's live top edge (`DesignFraming.VisibleFraction`, min 0.35). Expanded panel height: 50% of screen; a second detent at 80% for long edits (vehicle then min 0.35 via `MinVisibleFraction`). Panel contents:
1. Readout strip (46 pt; 3 cells kid, 6 cells engineer).
2. Category tabs, horizontal scroll chips 44 pt: Stack, Engines, Tanks, Boosters, Fairing, Payload, Recovery, Look (kid: Presets, Engines, Fuel, Payload, Look).
3. Stack list (part tree: fairing → upper stages → stage 1 → boosters) with issue badges; on SE it sits in the Stack tab, on Pro Max it stays above the parameters.
4. Parameter rows: label, value + unit, consequence hint, −/+ steppers 44x44 pt; long-press repeats; sliders only for continuous values with the same 44 pt thumb, always paired with steppers.
5. Launch, 50 pt, pinned above the bottom safe area, never scrolls.

**iPad 13in: side panel (400 pt, right).** Chosen over a wider bottom sheet because portrait iPad has the height to show the full vehicle and tower uncompressed, and tall stacks read best with full height. A bottom sheet would cut the rocket to ~50%. The panel also has room for the per-stage table, stack list and parameters at once. Needs a horizontal variant of `DesignFraming` (shift the projection in X by the panel width; §9 G2).

**Safe areas:** header below `Screen.safeArea` top + 8 pt (same as Home, SliceApp L135-136); Launch above the bottom safe area + 8 pt.
**Reduced flash/motion:** exploded and reframe animations, haptic payoff sparkle, and the validation pulse become instant/static when iOS Reduce Motion is on **or** the in-game Reduce Flashing toggle is on.
**Accessibility:** every control gets a VoiceOver label + value + hint (today the project uses tooltips as a stand-in, SliceApp L99/L149). Steppers are adjustable elements (swipe up/down). Value changes announce the new value and the readout delta: "Stage 1 engines, 9. Liftoff push 1.38." Validation changes announce once: "Launch unavailable. Too many engines for this width." 3D view: "Rocket, 2 stages, 2 boosters. Double-tap to reframe." Dynamic Type: labels scale to AX3; the readout strip wraps to two rows rather than truncating.
